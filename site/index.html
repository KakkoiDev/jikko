Jikko

Define, discuss, track, prove, and audit work in plain Markdown, for humans and agents.

Pre-release. Apache 2.0. Source on GitHub.

What it is

A Jikko workspace is a folder of ordinary Markdown files. Nothing is locked inside an application: you can read and edit it with any editor, keep it in Git, and hand it to a person or an AI agent.

A little structure gives the files meaning. YAML frontmatter says what a page is, [[links]] relate pages, ![[embeds]] compose them, @mentions address people, agents, and groups, and comments stay inside the Markdown they discuss. There are four kinds of page and no more:

Document
any Markdown file. Information, composition, and a durable place to discuss.
Task
type: task. Status, assignee, due date, dependencies, blockers, and the evidence that proves it done.
View
type: view. A saved query over the workspace, shown as a board, table, or list.
Identity
type: identity. A person, an agent, or a group of them, used for mentions, assignment, and permissions.

The jikko command and its built-in web server understand that structure: they validate references, filter every page by who may read it, evaluate views, merge concurrent edits, and give agents the same operations as humans with --json output.

Quickstart

  1. Make a workspace. init creates the folder, runs git init, writes your identity page, a welcome page and an open-work view, and prints a bearer token for you once. Only the token's hash is kept, in .auth.md, which init keeps out of Git. 
    export JIKKO_TOKEN="$(jikko init --dir my-work --identity alice)"
cd my-work
jikko tree
  2. Define and track work. Pages are ordinary Markdown; YAML frontmatter makes a task explicit. --commit records each change as one Git commit attributed to you. 
    printf '# Write the plan\n\nQuestions go to @alice.\n' | jikko create tasks/first --type task --file - --commit
jikko set tasks/first assignee alice --commit
jikko set tasks/first status doing --commit
jikko list --assignee me
jikko check          # reports broken references and malformed pages
jikko log
  3. Serve it. The web interface is embedded in the binary and binds to localhost. 
    jikko serve
# open http://127.0.0.1:8080 and log in with the token
    Every page has a rendered view with its properties, backlinks, and discussion; those allowed to change it get an editor and comment forms. A save made against an old revision is merged, or shown side by side to settle.

Add --dir /path/to/workspace to any command to run it from elsewhere. Pass --json to list, show, tree, view, mentions, and check for output meant for scripts and agents.

Install

With Go 1.25 or later:

go install github.com/KakkoiDev/jikko/cmd/jikko@latest

Prebuilt binaries for Linux, macOS, and Windows, with checksums, are attached to each GitHub release once a version is tagged. A Homebrew tap (brew install KakkoiDev/tap/jikko) is published from the same release and will be documented in the README when it is live.

For agents

Jikko is meant to be the place where humans and agents meet over the work. An agent authenticates as an Identity, reads the permission-filtered workspace with jikko tree, show, and mentions, then writes back goals, decisions, progress, and evidence with the same structured operations (create, set, comment, save, upload). Git-backed workspaces can record a batch of changes with jikko commit, which attributes the commit to the actor. Start with agent.md.

Read the specifications

  • README: the full tutorial and command reference.
  • specification-v1.md: the source format, page kinds, references, and the work model.
  • identity-permissions.md and permission-semantics-v1.md: identities, authentication, and the permissions policy.
  • architecture-browser.md and browser/README.md: the server-first web interface and the read-only browser/WASM runtime.
  • ux-plan.md: product decisions and what is still planned.
  • SECURITY.md: what the permission model does and does not protect.

Jikko is an early specification and reference implementation. The web server binds to 127.0.0.1 and has no transport security of its own; put it behind a TLS-terminating proxy to reach it from elsewhere.
